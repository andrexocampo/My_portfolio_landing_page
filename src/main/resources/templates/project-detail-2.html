Maintenance Manager

A web app to centralize vehicle maintenance, track upcoming services, and monitor costs for one or multiple vehicles.

Stack: Spring Framework 3.5.6, Java 21 LTS, Spring Data JPA/Hibernate, Spring Security, MySQL, Thymeleaf, Bootstrap 5, Chart.js, Maven, Git — MVC, DAO

View on GitHub

Executive summary

Maintenance Manager is a web application built to simplify vehicle maintenance. It centralizes fleet data, schedules upcoming services, and sends alerts before due dates so you can plan and avoid costly oversights. The app also keeps cost history and generates clear statistics, turning maintenance chaos into something manageable and predictable.

The process: how I built it

Identifying the problem

Keeping track of oil changes, inspections, and other maintenance tasks by hand is stressful and easy to forget. Spreadsheets and sticky notes don't scale when you have more than one vehicle, and missed services can lead to costly breakdowns. I wanted a tool that would centralize everything, remind me when maintenance is due, and give me a clear view of spending over time.

Defining scope and tools

I chose a web app so it would be accessible from any device. Spring Boot suited the project well for a modular backend with built-in security and persistence. I used Spring Data JPA with MySQL for the database, Spring Security for authentication, and Thymeleaf with Bootstrap 5 for the UI. Chart.js handles the cost charts. Maven and Git managed dependencies and version control. For production, I added email notifications to remind users when maintenance is due.

The design process

The starting point

I started by creating the project with Spring Initializr and setting up the package structure. I then identified the main entities (vehicles, maintenance types, service records, and users) and planned how to present them to the user, keeping the layout minimal and direct so that key information was easy to find and act on.

Designing the database

I started from the domain: I designed the entity classes (vehicles, maintenance types, service records, users) and their relationships—one-to-many, many-to-one—directly in Java. Once the models were clear, I relied on JPA/Hibernate to generate the schema: tables, columns, foreign keys, and indexes were created from the entity definitions.

Designing the architecture

I adopted a layered MVC structure: controllers for HTTP and routing, services for business logic (reminders, aggregations), and Spring Data JPA repositories for persistence. Spring Security protects routes and sessions. The design is modular so that analytics or new features can be added later without changing the core.

Designing the UX/UI

I sketched several wireframes first and then selected the final ones. The criteria I used to choose them were simplicity and efficiency, with tables ordered by age so that the most urgent maintenance items appear first. The home page also has alert signals to remind you of upcoming due dates, notifying you weeks and days before something is due, and also flagging overdue items. Finally, I added a statistics section with relevant information such as total money spent on maintenance over the last year and budgeted cost for the coming months.

Implementation and results

I built the project incrementally: data model and repositories first, then authentication, then CRUD for vehicles and maintenance records, and finally the reminder logic and Chart.js dashboards. Email notifications were added for production. The result is a functional web app that centralizes maintenance, alerts users in advance, and tracks costs over time. The modular architecture makes it straightforward to extend with more analytics or integrations.
