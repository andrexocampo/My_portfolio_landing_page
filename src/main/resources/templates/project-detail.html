Defstuf

A Java desktop app to collect definitions and theorems, practice with spaced repetition, and keep everything in one place.

Stack: JavaFX 13, MySQL 8.2, JDBC, Maven, Git, BCrypt — MVC, DAO

View on GitHub

Executive summary

Defstuf is a Java desktop application built to centralize and streamline how you study core concepts. It uses an integrated clipping tool and spaced repetition to make capturing and memorizing content easier. The app also helps you organize knowledge into study areas and keep track of source references.

The process: how I built it

Identifying the problem

When learning new theories or complex topics, two steps often feel tedious and inefficient: gathering information and then memorizing it. Copying definitions from PDFs, slides, or web pages can become a heavy task, and managing many concepts gets messy. Even after that effort, you still face memorizing each concept without losing detail and reviewing in a scattered way—sometimes repeating what you already know and neglecting what needs more attention.

Defining scope and tools

I chose to build a Java desktop application and put mobile and web aside for now. That fits the usual study setup, where a clipping tool that’s always at hand and works smoothly with PDFs, slides, and the browser matters most for students and professionals in maths and science.

For the build, I used JavaFX for the UI, MySQL for persistence, and Maven for project and dependency management, plus Git for version control. Passwords are hashed with BCrypt, and JDBC gives direct control over SQL without adding an ORM.

The design process

The starting point

I began with a brainstorm on main needs and possible solutions. Ideas came up like a timeline for scheduled sessions, a window to inspect user results and progress over time, and others. As a first step, I decided to add the clipping tool plus the note-management and spaced-repetition modules, since they had the strongest impact on the problem with lower cost in time and effort. I then wrote a requirements list and used it to plan and implement each module.

Designing the database

I sketched several database layouts to pin down the most relevant data for the app. I looked at smaller schemas focused on clarity and maintainability, and at more robust ones for flexibility and richer analytics. I settled on a middle ground: a database with three main sections and three normalisation levels.

Section one handles core CRUD: areas (study areas), notes (each concept), note_type (so we can add types beyond definitions and theorems), sources (for books or other references), and images (attached to notes).

Section two covers study sessions: study_sessions (session setup and analysis), questions (links sessions, questions, and user answers for analytics), answers (valid answers), and scheduled_reviews (spaced repetition).

Section three stores user and stats data: users (account data), user_statistic (user metrics), and statistics_type (to support flexible stat names, values, and types).

Designing the architecture

I used a modular, layered setup with MVC: a presentation layer (FXML views and controllers), a service layer (business logic), and a persistence layer (repositories implementing the DAO pattern). Domain modules are area (study areas), note (notes, sources, images), screenshot (clipping tool wired into notes), study (session setup, execution, and spaced repetition), and user (user model and persistence), plus auth (login, signup, authentication). Most of these have their own packages in each layer; the screenshot module has no separate repository and uses the note one to store images.

Designing the UX/UI

I iterated on wireframes and dropped options that didn’t feel balanced or clear. I prioritized making it easy to start a review—for example, “Start Review” prominent in the main menu—and grouping session options (area, sources, duration, card limit, order) on a single screen before starting. I aimed for clear, comfortable layouts for notes and areas: tidy forms, list-as-cards, distinct panels. Using JavaFX, I went with a dark, low-glare palette, soft neumorphic-style panels, and strong contrast on primary actions via an orange accent.

Implementation and results

I set up a stable folder structure and added modules step by step: initial DB connection setup, JavaFX as the UI framework, the clipping tool, then the “create note” flow (including image attachments from the clipper). Next came authentication, the DAO-based repositories and MySQL integration, and study sessions with spaced repetition. Finally, I applied the neumorphic UI style and tuned layout (windows, panels, scroll) for better balance. Git supported the whole process—main work on develop and feature branches for larger changes.

The result is a working, tidy application that’s flexible and scalable, and that tackles common friction when studying maths and science in typical desktop setups.

Technologies used (detail)

Backend / core

  • Java 11+ — Runtime and language for the application.
  • Maven — Build, dependencies, and packaging.
  • MySQL 8.2 — Persistent storage for users, study areas, concepts, and review history.
  • JDBC — Database access and SQL control without an ORM.
  • BCrypt — Hashing and verification of user passwords.

Desktop UI

  • JavaFX 13 — Windows, forms, and controls for the desktop interface.

Design and workflow

  • MVC — Separation between views (JavaFX), controllers, and domain/service logic.
  • DAO — Data access behind interfaces so the rest of the app does not depend on SQL or schema details.
  • Git — Version control and project history.

Conclusion and learnings

Defstuf turned out to be a good exercise in scoping and in designing for change. Defining “concept” and “review event” clearly made it straightforward to add new concept types and tune the repetition algorithm. I got more comfortable with JavaFX and with modeling time-based, user-specific data in SQL. If I were to extend it, I’d add simple analytics (e.g. retention per study area) and, in a later phase, a sync or lightweight web companion, reusing the same core services and DAOs.
